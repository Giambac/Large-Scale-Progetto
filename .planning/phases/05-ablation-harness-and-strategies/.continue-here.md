**Strategy mechanics (ALAB-01)**
- UncertaintyDrivenStrategy: target highest-uncertainty cluster (lowest mean soft-assignment confidence from f_uncertainty). Payload carries cluster_id.
- BoundaryDrivenStrategy: find most-confused cluster pair (A,B) by mutual soft-assignment overlap → collect ALL items confused between A and B → show as a coherent group. Payload: {cluster_a, cluster_b, item_ids}. User explicitly rejected single-point focus: "chat about a single point is useless conversationally."
- Degenerate fallback (no valid target): emit ask_question with generic payload — hand initiative to oracle. Logged as deviation(). NOT a crash, NOT random fallback.
- Oracle conversational initiative: full freedom within response already works. No oracle-initiated turns needed for Phase 5.

**Harness design (ALAB-02)**
- 3×3×3 = 27 runs default, tunable via config. 3 strategies × 3 personas × 3 seeds.
- Parallel execution via ThreadPoolExecutor, configurable max_workers. Each run gets its own sqlite3.Connection (WAL mode supports concurrent connections).
- Config: cross-product YAML with optional exclude list for specific combos.
- Entry point: examples/run_harness.py + src/harness.py importable function.

**oracle_type DB field (EXP-V2-01 partial)**

## Critical Anti-Patterns (do NOT repeat these)

- **SINGLE-POINT ORACLE FOCUS**: BoundaryDriven must target a GROUP of items sharing the same boundary ambiguity — never a single isolated point. Single-point questions are useless in conversation unless tied to generalization. Structural prevention: BoundaryDrivenStrategy.select() must collect item_ids list (plural) and assert len(item_ids) > 1.
- **PLACEHOLDER MESSAGES**: _format_message() currently sends "Showing a subset of clusters at turn X." for show_subset — this is dead content, the oracle LLM gets nothing useful. Phase 5 MUST enrich this before running any harness experiments.
